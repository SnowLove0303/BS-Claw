# 最新规范问题清单

## BF-P2-010 中文菜单缺少启用/停用入口

- 实际流程：菜单可注册、列表、详情、编辑、删除、检测、打开和全量检测，但没有 Enable/Disable。
- 用户影响：用户必须离开菜单并记忆命令行 Action 和资源编号才能完成已实现的启停功能，入口不完整、学习成本高。
- 简化方向：在资源详情或资源操作菜单中直接提供“启用/停用”，根据当前状态只显示可执行动作，并复用统一确认和反馈。
- 人工复验标准：从中文菜单不输入命令名即可完成启用和停用，列表/详情状态同步变化。

## BF-P2-011 交互式编辑单字段需要经过 11 个字段提示

- 实际流程：选择编辑后，系统依次询问资源名称、主机、端口、连接方式、浏览器程序、配置目录、页面地址、平台规则、登录规则、启用状态和备注，即使用户只修改一个字段也需要处理全部提示。
- 用户影响：步骤冗余、理解成本高、容易误输入或误改，违反最少步骤原则。
- 简化方向：先选择要编辑的字段，再只询问该字段；或在详情页提供按字段编辑入口，默认保留其余值且不要求用户重复判断。
- 人工复验标准：只修改资源名称时，用户最多经过目标字段和确认两步，其余配置不变。

## BF-P2-012 注册流程对普通用户暴露过多底层概念

- 实际流程：Launch 注册涉及连接模式、浏览器可执行文件、F 盘配置目录、起始页面、平台匹配规则和登录规则等多组技术字段。
- 用户影响：用户需要理解 CDP、浏览器配置目录和页面匹配规则才能完成业务目标，入口虽可运行但不够用户友好。
- 简化方向：默认使用 ConnectOnly；只在用户选择“需要自动启动浏览器”后展开必要配置；页面规则优先由真实起始页面自动生成，复杂规则放入高级设置。
- 人工复验标准：普通 ConnectOnly 注册只需提供名称、端口和必要页面信息，不要求用户理解底层协议名。

## BF-P2-013 菜单重定向输入无法正确解析

- 实际流程：使用 PowerShell 标准输入自动执行菜单，输入 `0` 或 `2` 后，程序将输入解析为 `System.Collections.ArrayList+ArrayListEnumeratorSimple`，随后提示“输入无效”。
- 用户影响：菜单无法被自动化脚本、管道和回归测试稳定驱动；也无法满足简单 PowerShell 指令的自动验证体验。
- 简化方向：统一把菜单输入转换为单一字符串并处理数组/枚举器输入，确保 `0`、`2` 等中文菜单路径可由标准输入稳定执行。
- 人工复验标准：通过标准输入发送 `0` 能正常退出，发送 `2` 能查看列表，不出现枚举器文本和无效输入提示。
