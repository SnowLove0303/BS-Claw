# 热试车问题与未验证项

## BF-P2-014 自动回归脚本未完成最终汇总

- 位置：`tests/run-business-regression.ps1`。
- 实际表现：热试车执行到真实 Launch 资源注册后，未生成 `business-regression-summary.json`，也未输出最终通过/失败汇总；运行日志停留在 Launch 后续流程阶段。
- 影响：自动化验收无法形成完整机器可读结论，用户无法一次获得所有用例的通过数、失败数和证据路径。
- 类型：测试基础设施/验收流程缺陷。
- 建议：为每个阶段增加超时、异常捕获和 finally 汇总；无论单项失败、外部进程异常或脚本中断，都必须落盘 summary，并明确未验证项。
- 复测：重新运行完整回归脚本，必须生成 summary，且包含所有用例及最终退出码。

## BF-P2-015 Get-NetTCPConnection 失败日志重复噪声

- 位置：端口拥有者检测与日志回退路径。
- 实际表现：系统反复记录 CIM `MSFT_NetTCPConnection` 无匹配实例的 WARN，再回退 netstat；热试车中同一端口产生大量重复 WARN。
- 影响：日志噪声过高，掩盖真正故障，增加审计和人工排查成本。
- 类型：可观测性/体验问题。
- 建议：区分“无监听结果”和“检测命令异常”；无监听不应按 WARN 重复记录，真实命令异常应限频并保留一次结构化诊断。
