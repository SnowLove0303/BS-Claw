# 端口管理模块最终审计与提交准备报告

## 结论

本轮未达到“可直接提交/可推广”标准。端口管理核心链路已具备真实验证证据，但主登录代理的仓库归属、发布基线、敏感测试输入保护、登录业务回归契约和交付目录隔离仍需先收口。当前已建立独立发布分支，未提交、未推送。

## 审计范围

本报告合并代码审计、业务流程审计、PowerShell 独立验证、存储审计与 Qoder（better-harness）审计。Qoder 会话证据没有采集到可分析会话，因此不以它评价线程行为；其项目规则和资产审计结果只用于交付治理结论。

## 已验证事实

- 静态验证 8/8 通过：35 个 PowerShell 脚本语法解析、JSON、SQLite Python 服务、空数据启动、中文菜单退出、根入口 Action 对齐、交付路径和主系统隔离均通过。
- 隔离资源的慧策端到端登录、ERP 页面到达、接口探针、状态同步、SQLite 完整性、租约释放与同资源二次复用均已在本轮审计中独立执行并保留非敏感结果。
- 本次清理后，当前隔离资源仍返回 `logged-in-api-ready`，页面为 ERP，端口为 53396，浏览器 PID 复用，活动租约为 0。
- 端口管理 SQLite 与登录代理 SQLite 的 `integrity_check` 均为 `ok`。

## 已清理与保护范围

已通过模块的受控 `CleanCache` 路径清理两套已停止登记资源的可再生 Chrome 缓存，计划清理量分别约 3.10 GB 和 3.10 GB。清理后两者均无剩余可清理缓存计划。

本次没有删除 Cookies、本地存储、会话存储、Profile SQLite、资源定义、CredentialRef、脱敏账号摘要、审计记录、登录会话事件、数据库 schema 或任何仍在运行的 Profile。

历史测试运行目录与运行时浏览器测试目录合计约 1.38 GB，均属于可重建数据；递归删除受当前执行环境的安全策略拒绝，未绕过该限制，仍待在本机按已确认路径清理。

## Qoder / better-harness 结论

Qoder Canvas 报告已生成，结构校验通过；因目标项目未安装 Qoder Canvas SDK 声明文件，运行时类型校验显示警告，不影响报告数据和 Canvas 合同校验。

需在提交前解决的 findings：

1. 最终版尚未形成受控的发布基线：运行代码、文档、测试和审计产物仍混合在已修改/未跟踪工作树中。
2. 主登录代理目前位于同级目录，既不在当前仓库跟踪范围内，也没有独立 Git 根；单独提交端口管理仓库无法复现真实登录链。
3. 本地明文测试凭据文件此前不受忽略规则保护；本轮已加入精确忽略规则，文件未被提交或输出，但仍应迁移到受控输入或凭据引用。
4. 业务回归中仍有一条过期断言，把当前已实现的登录能力判为未实现，导致 19/20 而非完整通过。
5. 可再生产物和浏览器缓存仍须从最终交付目录完全隔离；源码包不得带入测试运行目录或完整 Chrome Profile。
