# 选品模块首个垂直业务案例补充派发

## 任务目标

首个正式交付目标不是“选品模块代码存在”，而是在真实慧策环境完成一个商品的“选品加入分销”业务闭环，并以该真实路径固化第一版选品工作流标准。

## 目标结果

```text
Codex/用户提出加入分销目标
 -> 统一调度层识别选品加入分销
 -> PortManager 自动匹配资源
 -> 端口/CDP/Profile/登录/API-ready/权限/租约预检
 -> 慧策真实候选读取
 -> 按已确认规则自动确定目标商品
 -> 慧策真实加入分销调用
 -> 分销商品列表/详情精确回查
 -> 返回商品已加入分销的业务结果
 -> 脱敏审计、任务状态落地、租约释放
```

## 必须先真实执行再抽象

1. 使用当前真实、可用、已登录 API-ready 资源完成候选读取。
2. 使用真实慧策响应确定商品标识、供应商上下文、加入分销请求体和结果回查字段。
3. 选择一个授权、隔离或可回滚的真实商品执行加入分销；不使用 mock、固定样例或假成功。
4. 对加入分销结果做精确回查，确认真实业务对象已进入分销状态。
5. 记录真实过程中的调度、资源、API、状态、错误、租约和回查证据。

## 真实案例完成后必须固化

- 业务目标和用户入口；
- 调度层、PortManager、登录代理、选品模块、HTTP connector 的责任边界；
- 每一步输入、真实数据来源、输出和状态变化；
- 加入分销的真实 API/字段/幂等/回查契约；
- 自动执行和无业务确认的边界；
- 登录失效、资源占用、候选为空、业务拒绝、重复加入、超时、取消和未知结果处理；
- 租约释放、审计记录和恢复路径；
- 可复用为后续选品 Action 的标准工作流模板。

## 禁止收口方式

- 不能只返回候选列表；
- 不能只返回 HTTP 200、taskId 或本地任务记录；
- 不能只完成规则筛选而不加入分销；
- 不能只调用加入分销接口而不回查；
- 不能把“等待授权”当作完整业务成功；
- 不能在没有真实商品结果时宣称工作流完成。

## 当前线程协作规则

本补充不得中断技术线程正在进行的真实候选链；当前动作完成后立即进入本垂直案例。若真实写入需要用户授权，使用正式等待式入口，并在授权后继续执行，不让用户拼接命令、JSON 或凭据。
