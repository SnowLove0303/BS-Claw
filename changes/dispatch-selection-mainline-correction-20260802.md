# 选品模块主干开发任务校正

## 校正原因

上一版派发任务把“未经核验不得伪造成功、写入需授权隔离”过度表达成“暂不接入真实 API、只做骨架”。这偏离了用户要求：必须基于现有慧策真实环境、PortManager、HuiceLoginAgent 和统一调度能力推进真实选品主干。

## 校正后的开发目标

技术线程必须在不泄露凭据、不绕过登录和不破坏正式数据的前提下，使用现有正式资源的真实状态和真实慧策 HTTP API 完成候选读取链；在用户已授权的隔离/可回滚资源上完成第一个真实选品写入 Action、精确回查和状态收口。禁止用 `HTTP_INVOKER_NOT_BOUND`、`RULE_IMPLEMENTATION_PENDING` 或 `WRITE_ACTION_NOT_VERIFIED` 作为长期实现替代。

## 允许并要求的真实工作

- 复用现有已登录且 API-ready 的 PortManager 资源进行真实只读 API 调用。
- 通过已有调度层和公开资源适配器取得 ResourceContext，不直接读 PortManager SQLite。
- 读取并核对 Feishu 文档、Pynes 代码和真实慧策响应，形成真实字段映射。
- 先完成候选读取、分页、响应归一化和实际结果落库，再实现规则和 Action。
- 在明确授权的隔离或可回滚资源上执行真实写入并精确回查；不因“不能盲写”而不实现写入链。
- 将真实 API 错误、权限不足、登录过期、业务拒绝和结果不确定作为真实状态处理。

## 仍不可做的事

- 不读取、输出或保存密码、Token、Cookie、完整授权头或 Profile 敏感内容。
- 不在未授权的正式资源上做破坏性写入、删除或清理。
- 不把诊断脚本、固定样例或 mock 当作真实结果。
- 不绕过 PortManager、登录门禁、租约和调度状态。

## 新的完成门槛

至少必须形成：真实候选 API -> 真实响应 -> 真实规则处理 -> 第一个真实选品 Action -> 真实结果回查 -> 状态/审计/资源释放。若真实写入受外部授权阻断，必须先完成真实只读主干和可执行写入代码，再明确记录具体外部阻断，不得把整个模块停留在接口占位状态。
