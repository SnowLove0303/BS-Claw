# 选品模块 Phase 1 主干独立审计结果

## 结论

结论：退回整改，当前不能登记为选品功能完成、可交付或可进入正式发布。

准确表述不是“完全没有代码”，而是“存在可运行的模块契约、预检和状态持久化骨架，但没有实际选品业务闭环”。

## 现场证据

- 实际目录：`F:\XIANGMU\BS Claw\SelectionModule-Phase1`。
- 分支：`feature/selection-module-phase1`，当前无 Git 提交，工作区为新增文件现场。
- 静态验证脚本实际返回 `ok=true`，PowerShell Parser 无错误，manifest 可解析，Discover 可返回模块/适配器信息。
- 空资源上下文执行实际进入 `AUTH_REQUIRED`，能够生成任务记录、资源快照和状态结果。
- `Selection.Candidates.psm1` 明确返回 `HTTP_INVOKER_NOT_BOUND`，没有受控慧策 HTTP 调用句柄。
- `Selection.Rules.psm1` 明确返回 `RULE_IMPLEMENTATION_PENDING`，没有实际筛选/排序/去重规则。
- `Selection.Actions.psm1` 明确返回 `WRITE_ACTION_NOT_VERIFIED`，没有执行真实写入或结果回查。
- 全部实现脚本和模块中未发现 `Invoke-RestMethod`、`Invoke-WebRequest`、`HttpClient` 或正式慧策 API 调用实现；API 路径只存在于参考文档。
- 变更记录明确写出：正式 API 字段绑定、规则、外部写入、BSClaw-Local 自动发现和端到端用户路径均未实现。

## 一级代码架构审计

通过项：

- PowerShell 模块拆分基本形成：入口、契约、数据库、状态、预检、候选、规则、Action、恢复。
- 独立 SQLite 表和迁移文件存在，未直接访问 PortManager SQLite。
- manifest/adapter 有能力、资源策略、登录门禁、写入风险和回查字段。
- 敏感字段保护意图和脱敏结果结构存在。

不通过项：

1. HTTP connector 实际不存在，候选模块只有阻断返回；“候选获取”不是实现。
2. 规则模块只有接口占位和阻断返回；“筛选/排序”不是实现。
3. Action 只有幂等键生成和阻断返回；没有外部动作、回查或恢复执行。
4. BSClaw-Local 自动发现注册尚未实现，adapter 只是本地 JSON 文件，不代表调度已接入。
5. SQLite 运行时在缺少模块本地 Python 时回退到同级 PortManager 工具路径，削弱独立可迁移性。
6. `Invoke-SelectionPreflight` 在空对象和 null 上的处理不完全一致；字段读取发生在 null 判断前，真实 null 可能落入入口级异常而非规范化预检结果。

一级结论：代码骨架可读，但主干业务实现不足，一级不通过。

## 二级业务交互审计

不通过。

- 没有接入 BSClaw-Local 正式用户菜单、向导或 Codex 业务入口。
- 用户无法从真实入口提出选品目标并看到候选、筛选结果或业务结果。
- “Discover/Preflight/Execute/Status...”是技术入口，不能证明用户功能完成。
- 资源上下文必须由调度层注入，调度层实际绑定是否完成没有证据。
- 全自动业务确认虽已关闭，但没有任何可执行业务动作；当前只能自动阻断。
- 结果只证明门禁/契约状态，不能帮助用户完成选品目标。

## 三级真实路径审计

不通过，且主成功路径无法成立。

已实际执行：

1. 静态验证脚本。
2. Discover 入口。
3. 空资源上下文 Execute，结果为 `AUTH_REQUIRED`。

上述只证明模块能发现自己、能阻断不合格资源并写入本地任务状态，不能证明：

- 从 PortManager 正式源库自动选择资源；
- 从登录态资源获取真实慧策候选；
- 应用选品条件；
- 执行选品动作；
- 精确回查业务对象或任务；
- 返回用户可用的最终业务结果；
- 完成真实租约申请/释放和跨模块状态一致性。

没有真实候选数据、真实 API 调用、真实写入和真实结果回查，三级不能通过。

## 四级治理审计

退回整改。

- 资料包与任务包已形成，技术线程也保留了“不伪造成功”的边界，这是合规的。
- 但需求 SEL-01～SEL-10 的核心业务结果未实现，至少 SEL-04、SEL-05、SEL-06、SEL-08 未闭环。
- 未建立独立 Git 提交基线；当前不能称为正式发布候选。
- 未形成 BSClaw-Local 自动发现、正式用户入口、真实 API、隔离授权资源和回滚证据。
- 不能把静态验证通过、Discover 返回或安全阻断结果包装成选品功能完成。

## 必须整改

P0：

1. 接入受控慧策 HTTP connector，至少完成候选只读 API 的真实请求、响应归一化、分页、错误、限流、脱敏和来源时间。
2. 在需求条件冻结后实现真实 candidate.filter，包括条件、排序、去重、缺失字段和命中/淘汰原因。
3. 明确首个真实 selection Action 的业务语义；实现隔离资源上的真实写入、幂等、未知结果回查和结果落地。
4. 通过 BSClaw-Local 公开契约完成模块自动发现和资源上下文真实注入，不只保留本地 adapter 文件。
5. 从正式用户入口走通：用户提出目标 -> 系统匹配资源 -> 预检 -> 候选 -> 筛选 -> 自动执行 -> 回查 -> 结果展示。

P1：

1. 移除或配置化同级 PortManager Python 回退依赖，保证模块可迁移和可重建。
2. 修正 null/空上下文预检和所有错误契约边界。
3. 补齐取消、超时、异常退出、未知结果恢复和租约状态的真实跨模块验证。
4. 建立独立 Git 初始提交/回滚点；不得修改既有仓库 dirty 工作树。

## 放行条件

只有在真实入口、真实候选、真实规则、真实 Action、精确回查、状态/数据一致、资源释放和一至四级证据齐全后，才可重新审计。当前结论为“骨架存在、实际选品功能未形成、退回整改”。
