# BS Claw 用户人工测试

## 1. 测试目标

确认普通用户只输入 `bsclaw`，即可通过中文菜单查看本地服务、端口资源、登录门禁和最近任务，并由系统自动执行、等待和回查。用户能区分纯展示、服务状态检查和业务写入，不需要填写模块编号、动作名、任务编号或 JSON。

本阶段不执行选品、分销、订单等业务写入，也不会自动清缓存、删除资源或登录慧策。

## 2. 前置条件

1. `BSClaw-Local` 与 `PortManager-Phase1` 位于 F 盘。
2. 新开一个 PowerShell，执行 `Get-Command bsclaw | Select-Object -ExpandProperty Source`。
3. 结果应以 `BSClaw-Local\tools\command-launcher\bsclaw.cmd` 结尾。若显示 PortManager 目录或找不到命令，执行：

```powershell
powershell -NoP -EP Bypass -File "F:\XIANGMU\BS Claw\BSClaw-Local\install-bsclaw-command.ps1"
```

4. 安装提示成功后关闭当前 PowerShell，再新开一个 PowerShell 重做第 2 步。若项目已迁移到其他 F 盘目录，只替换上述命令中的 `BSClaw-Local` 实际路径。
5. PortManager 目录中的同名命令只是兼容入口；它可以继续转发，但不应成为 `Get-Command bsclaw` 的首选结果。
6. F 盘 Python 已准备完成。若启动器提示缺少 Python，请按提示执行 `prepare-python.ps1`；程序不会自动下载到 C 盘。
7. 不要在截图或反馈中提供密码、Cookie、Token、完整授权头或 Credential 实值。

## 3. 进入和退出

在新 PowerShell 输入：

```powershell
bsclaw
```

预期看到 0 到 9 的中文菜单。输入 `0` 应安全退出。

通过标准：菜单无 JSON、无内部动作名、无任务编号要求；用户能看懂每个入口。

旧版本判断：若菜单没有“本地服务”“执行模块”“任务与审计”三个分区，或总览提示当前从兼容入口启动，应先按第 2 节重新安装正式入口并重开 PowerShell，不继续用该现场做验收。

## 4. 查看本地服务总览

1. 输入 `1`。
2. 查看端口管理、慧策资源、本地服务插件和业务模块状态。
3. 若只接入 PortManager，应显示“本地服务插件：已接入；业务执行模块：暂无可用业务模块”。
4. 可输入 `1` 运行完整服务检查；系统会自动等待并显示结果，不要求复制任务编号。
5. 输入 `0` 返回。

失败标准：把 PortManager 说成业务模块；旧快捷入口没有提示刷新 PowerShell；检查后要求用户另输命令查询结果。

## 5. 查看资源列表和详情

1. 主菜单输入 `2`。
2. 查看所有资源的资源编号、端口、状态和下一步建议。
3. 输入任一资源前的序号。
4. 系统自动读取并回查详情，然后展示端口连接、登录状态、只读接口和最近检查时间。
5. 在详情输入 `1` 重新检查；检查结束后资源编号、端口、名称和平台必须仍然存在，后续操作仍关联同一资源。
6. 输入 `0` 返回资源列表，再输入 `0` 返回主菜单。

资源编号是资源标识，不是账号或凭据。详情不得显示密码、Cookie、Token、完整授权头或 Profile 内部文件。

## 6. 查看登录门禁

1. 主菜单输入 `3`。
2. 查看“可继续、需登录、未验证、不可用/需修复”的数量。
3. 可输入资源序号查看详情。

预期：需登录资源提示走正式登录入口；未验证资源提示重新检查；不能用 Chrome 正在运行替代登录成功。

资源详情中的操作：

- `1` 重新检查状态：执行真实服务状态检查，会更新检测时间、运行状态、临时租约和审计记录，但不改 schema、资源定义、凭据、Profile 或外部业务；
- `2` 打开或复用资源：必须输入“确认”，否则不操作 Chrome；
- `3` 查看存储与缓存：只读，较大 Profile 可能等待几十秒；
- `4` 正式登录：必须输入“确认”，随后按 PowerShell 提示处理；
- `0` 返回。

本轮自动测试覆盖纯展示和服务状态检查路径。打开 Chrome 和正式登录必须由用户明确确认，不能算作本轮自动通过项。

## 7. 查看系统诊断、审计和模块

- 主菜单 `4`：诊断同时列出系统项与资源级未验证/需登录情况。
- 主菜单 `6`：按本地服务与执行模块分区展示；未接入业务模块时不得出现可运行入口。
- 主菜单 `8`：查看最近检查记录。
- 主菜单 `9`：依次选择检查对象和检查方式，生成脱敏审计摘要。

诊断或审计不得把“未验证”写成通过。

## 8. 使用调度任务中心

1. 先完成一次服务检查或资源详情检查。
2. 主菜单输入 `7`。
3. 最近任务按用户可理解的名称、状态、时间和摘要显示。
4. 输入任务序号查看详情。

任务编号和审计编号仅在“技术信息”中展示，供反馈问题使用；用户不需要复制它们才能继续。未完成任务可在详情中取消，可安全重试的任务会提供确认入口。

开发或审计检查产生的不支持操作、未接入模块记录会分别显示为“不支持的操作请求”“未接入模块请求”，并明确说明不影响菜单中的正常操作，不得笼统显示为“系统任务”。

## 9. 打开原端口管理

主菜单输入 `5`，应进入原 PortManager 中文菜单；在 PortManager 输入 `0` 后返回 BS Claw。原端口管理独立能力不得被统一层替代。

## 10. 通过与失败标准

通过：

- 用户只需 `bsclaw` 和菜单序号完成常用查看；
- 纯展示和服务状态检查自动创建任务、等待、回查并展示结果；
- 服务插件与业务模块明确区分；
- 资源状态和下一步清楚；
- 无敏感值泄露；
- 原 PortManager 入口仍可用。

失败：

- 要求用户手写 `moduleId`、`action` 或复制 `taskId` 才能继续；
- 把未接入模块显示为可执行；
- 把未验证资源显示为可用；
- 未确认就打开浏览器或登录；
- 输出凭据或浏览器存储；
- 原端口管理入口断开。

反馈时提供：所在菜单、操作时间、屏幕上的中文错误类型、脱敏结果和截图。不要提供账号、密码、Cookie、Token 或完整授权头。

## 11. 开发与审计接口（非普通用户主路径）

`bsclaw status --json --no-record`、`bsclaw task submit ... --json`、`bsclaw task result ... --json` 等命令仅用于开发、自动化和审计。它们保持兼容，但不能替代上述菜单验收。

## 12. 本阶段未覆盖

- 同端口/跨端口多任务并发、排队和抢占策略；
- 真实业务模块及业务写入；
- 真实登录和外部安全验证的自动验收；
- 未经用户确认的浏览器操作。

## 13. 数据变化判断

不要用 SQLite 文件哈希是否变化判断“业务写入”。资源状态检查会更新运行状态、检测时间、租约和审计，所以文件哈希可变化。验收需分别记录：schemaVersion/schema 定义未变；资源定义和凭据未变；运行状态按预期更新；Profile 未变；慧策 ERP 等外部业务没有写入。
