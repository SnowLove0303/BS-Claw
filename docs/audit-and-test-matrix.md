# 选品模块审计与测试矩阵

## 一级：代码架构审计

检查 PowerShell 主入口复杂度、模块拆分、重复逻辑、manifest 合法性、路径可迁移性、依赖、异常边界、SQLite 分层、性能退化和 PortManager/调度层独立性。证据包括静态诊断、语法检查、模块发现、契约校验和变更影响清单。

## 二级：业务交互审计

从用户目标进入，检查用户是否无需内部 ID、是否自动匹配资源、是否展示真实阶段/结果、是否区分认证阻断和业务确认、是否能取消/返回/重试、是否保留旧端口管理和调度入口。全自动策略的重点是：没有业务确认不等于无安全门禁。

## 三级：真实路径审计

使用正式启动入口、真实 PortManager 源库、授权测试资源和真实慧策接口，验证候选读取、条件筛选、写入、精确回查、状态落地、并发、超时、取消、异常退出和租约释放。诊断脚本、内部 API 或固定 JSON 只能作为辅助证据，不能替代用户主路径。

## 四级：终审治理

核对原始需求、十类编号、资料包、Feishu/Pynes 参考边界、Git/数据库/运行状态、前三级证据、旧功能基线、自动执行风险、人工测试文档、发布候选和回滚点。任一需求项或回归项缺失，否决放行。

## 用户人工测试文档最低结构

虽然 Phase 1 不设置业务确认，交付仍必须提供用户测试文档：进入选品业务入口 -> 提出目标 -> 系统自动匹配资源 -> 查看阶段和结果 -> 查看成功/阻断原因 -> 取消或恢复（如触发）。不得要求用户输入 moduleId、Action、taskId、resourceId、JSON 或长 PowerShell。

## 必测案例

1. 有可复用登录资源的自动成功路径。
2. 无可用资源的真实阻断和可恢复提示。
3. 登录态失效/API-ready 不满足时不执行写入。
4. 候选为空、字段缺失、规则无匹配的真实空结果。
5. 同资源冲突返回 `RESOURCE_BUSY`，租约不泄漏。
6. 外部写入后精确回查成功。
7. 外部结果未知时不盲重试，进入恢复。
8. 取消、超时、异常退出后的状态与租约回收。
9. 重启后任务和运行数据可恢复。
10. PortManager 与 BSClaw-Local 原有入口逐项回归。
