# 用户能力与未来工作流契约

普通用户入口分为本地服务、执行模块、任务与审计。菜单读取 manifest 的 capability 元数据，通用任务执行、等待、结果展示、失败恢复和任务中心不绑定某个模块。

本地服务提供资源、状态、登录门禁和诊断；执行模块是独立 Python 工作流。当前只有端口管理资源服务，没有正式业务模块，因此执行模块区只显示“暂无可用业务模块”，不提供假按钮。

未来慧策 HTTP 工作流的正式顺序是：选择或自动匹配资源 → 实时登录门禁 → dry-run/参数预览 → 用户确认业务写入 → API 执行 → 结果回查 → 脱敏审计。失败至少区分登录失效、权限不足、字段缺失、业务校验失败、接口失败、网络失败、外部风控和程序缺陷。

调度层只获得 ResourceId、脱敏上下文和 capability 声明；不得获得密码、Cookie、Token、完整授权头、CredentialRef 实值或 Profile 内部数据。资源并发策略尚未确认，非 `none` 策略继续阻断。
