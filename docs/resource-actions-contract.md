# 端口资源统一入口与后台检测

## 用户入口

在 PowerShell 执行 `bsclaw`，进入“资源生命周期管理”或“后台资源检测”。普通用户不需要填写模块编号、任务编号或 JSON。

| 用户操作 | 风险等级 | 是否写服务状态 | 说明 |
|---|---|---|---|
| 注册、编辑、启用、停用、删除 | 维护写入 | 是 | 逐项确认；删除要求精确确认文本 |
| 列表、详情、占用情况 | 展示读取 | 否 | 只读展示真实公共命令结果 |
| 单资源检查、全部检查、登录状态检查 | 服务状态检查 | 是 | 会刷新检测时间、运行状态和审计记录，不写业务数据 |
| 打开/复用、正式登录 | 外部影响 | 是 | 必须用户确认；沿用 PortManager 正式入口 |
| 后台检测启动/停止/状态 | 本地维护 | 只写本地 monitor 状态 | 通过 PortManager 公共 `List/Check` 获取状态，不读其数据库 |

## 边界

统一层只调用 `PortManager-Phase1\port-manager.ps1 -OutputFormat Json -NonInteractive`。不导入 PSM1、不读取 SQLite/Profile、不接触密码、Cookie、Token。PortManager 的资源定义和运行状态仍是事实源；`BSClaw-Local\data\monitor\state.json` 只是可再生的监控心跳与最近结果缓存。

后台检测发现进程不存在或心跳超过 45 秒时，界面显示“后台检测未运行或状态已过期”，不会伪装实时。停止只针对统一层自己创建的 monitor 进程，不会终止 Chrome 或 PortManager 进程。

状态分三层：

- “最近检查有效”：PortManager 最近一次真实检查仍在有效期内；不代表后台监控正在运行。
- “后台检测运行中”：统一层监控进程真实存在且心跳未过期。
- “后台检测未运行/状态已过期”：没有有效心跳，用户应选择启动或恢复。

## 恢复

“全部检查”完成表示检查任务本身完成，不等于全部资源可用。结果会分别统计：可用、需登录、需修复、连接不可用和未验证；用户应按资源结果处理，不以“成功数量”替代登录/连接结论。

停用资源后选择删除时，菜单会明确提示：删除前需要重新启用以满足端口管理的安全删除约束。用户确认后系统自动完成重新启用和删除；取消则保持停用，不会返回难以理解的底层租约错误。

监控进程异常退出后，重新进入菜单 11 选择“启动或恢复后台检测”。服务重启不会依赖旧 PID、旧租约或旧缓存；下一轮通过公共命令重新读取已启用资源。

“全部检查”采用可回查的分段任务：先读取待检查列表，再按资源并行执行单资源检查；任务中心显示总数、完成数、失败数、当前资源和逐资源结果。单资源锁保存在本地可再生 scheduler 数据目录，异常进程可通过 PID 回收；同一资源重复任务返回 `RESOURCE_BUSY`，不同资源可以并行。

锁记录同时保存进程启动令牌，避免 PID 被系统复用后误判为存活。程序重启或任务状态查询发现 worker 已死亡时，会将任务置为“未验证/需人工回查”，并清理确认失效的资源锁；不会自动重跑可能已经产生外部结果的任务。取消任务会终止插件子进程并释放资源锁。
