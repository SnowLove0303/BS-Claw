# 具体实现方法与开发顺序

## 1. 实现分层

### A. PowerShell 入口层

提供发现、预检、执行、查询、取消和恢复的可复现入口。入口只做参数边界、上下文创建和结果输出，不承载所有业务逻辑。

### B. 契约与模型层

定义 manifest、能力、Action、资源需求、状态、错误、结果和审计模型。所有模型使用稳定字段和版本号，未知字段保持兼容，敏感字段永不落盘。

### C. 调度适配层

通过 service manifest/adapter 被 BSClaw-Local 发现；接收调度层注入的资源上下文和公开服务能力。禁止直接访问 PortManager SQLite、直接管理租约或自行维护任务主状态。

### D. HTTP connector 层

统一处理基础地址、请求头引用、超时、分页、错误、脱敏、读写分类和回查。API 字段必须集中维护，不散落在 Action 逻辑中。

### E. 业务 Action 层

候选获取、筛选、执行、回查分别拆分；Action 只表达业务意图，执行细节在 connector/服务中完成。每个 Action 提供 dry-run/只读预检能力，但不能把 dry-run 结果伪装成正式写入成功。

### F. SQLite 状态层

保存任务快照、候选快照索引、规则版本、外部任务引用、脱敏结果和恢复信息。先确定 schema 和 migration，再写业务代码；不复用或修改 PortManager 的数据库。

## 2. 推荐开发顺序

1. 先冻结需求、边界、Action 契约和 manifest。
2. 建立 PowerShell 项目骨架与相对路径发现。
3. 接入调度层只读能力与 PortManager 资源查询。
4. 实现预检、资源绑定、租约和状态骨架。
5. 接入慧策只读候选 API，保存快照并验证响应。
6. 固化规则版本、筛选/排序/去重和结果解释。
7. 在隔离授权资源上实现写入 Action、幂等和精确回查。
8. 补齐取消、超时、异常、未知结果、恢复和租约释放。
9. 执行四级审计和旧功能回归。
10. 形成独立提交、发布候选、回滚包和用户人工测试文档。

## 3. PowerShell 质量要求

- PowerShell 5.1 兼容性以 PortManager 实际运行环境为准。
- 路径使用模块根相对解析，不硬编码本机临时目录、账号、端口或 Profile。
- 外部调用设置明确超时和取消信号；异常统一转换为契约错误。
- 写入动作默认不自动重试；重试前必须回查。
- 每个模块可单独语法检查、指令化运行和回滚。
- 结构化输出只输出脱敏字段，用户输出与技术日志分离。

## 4. 完成定义

“代码写完”不等于完成。必须有真实入口、真实数据、真实状态、真实外部结果、回查、异常恢复、资源释放、回归证据和回滚路径，才可进入终审。
