# 全自动执行门禁与验收规则

## 自动执行决策

当前阶段关闭“业务确认”能力：候选筛选和选品写入达到自动预检条件后直接执行，不弹确认窗口、不要求用户再次确认结果。

但以下不是业务确认，仍是不可绕过的安全/外部事实门禁：

- 账号未登录、验证码、外部风控、授权失效。
- 资源不可用、Profile 锁定、CDP 不可达、租约冲突。
- 权限不足、规则缺失、输入不完整、接口契约不匹配。

这些情况必须安全阻断并可恢复，不能自动输入凭据、不能输出凭据、不能伪造完成。

## 放行条件

只有同时满足能力发现、资源绑定、预检、权限、规则版本、幂等、执行、结果回查、状态一致和租约释放，才可报告业务成功。

## 不得放行

- 需要手工输入内部 ID。
- 模块只返回 HTTP 200、任务号或固定文案。
- 没有精确业务回查。
- 写入未知结果后盲重试。
- 端口、登录、租约或任务状态未收口。
- 选品条件尚未定义却把默认值当正式业务规则。
- 只验证技术 CLI，没有真实用户/Codex 调度入口。

## 证据分层

开发自检、一级代码架构审计、二级业务交互审计、三级真实路径审计、四级治理终审必须分别记录；全自动策略本身也必须作为正式需求和回归项审计。
