# 选品模块 Phase 1 需求基线

## R0 目标与边界

用户通过自然语言提出选品目标后，Codex/统一调度层应选择已登记的选品能力，自动匹配可用资源、登录态、权限和执行条件，并完成选品动作，最终返回可判断、可回查的业务结果。用户不需要了解模块名、Action、任务 ID、资源 ID、端口或 JSON。

本阶段只做全自动业务链：不设置选品业务人工确认、不要求用户在候选结果前再次确认。自动提交前必须完成系统预检；预检失败时自动停止，不得将失败伪装成成功。

## R1 用户入口

入口不是独立的技术 CLI 参数，而是统一调度层接收的业务请求。调度层解析目标后自动选择 `selection` 模块和动作。技术 CLI/API 仅作为内部调用和审计取证入口，不能作为普通用户完成路径。

## R2 标准自动路径

1. 接收用户选品目标及必要业务参数。
2. 发现并校验选品模块 manifest、版本、能力和契约。
3. 从 PortManager 正式源库读取可用资源，自动绑定内部资源标识；用户不输入内部编号。
4. 检查端口、Chrome/CDP、Profile、登录态、API-ready、租约和并发策略。
5. 若已有满足条件的登录资源，自动复用；若没有，按外部授权门禁阻断，不能把缺少登录凭据变成“自动登录成功”。本阶段不设置业务确认。
6. 固化不可变的任务输入快照、资源快照、策略版本和幂等键。
7. 获取候选数据，按已登记条件执行筛选与排序。
8. 执行允许的选品动作。
9. 对写入结果做精确回查，不能以 HTTP 成功、任务入队或页面打开代替业务成功。
10. 记录脱敏审计、任务状态、外部任务号、结果摘要、失败原因和下一步。
11. 正常或异常结束均释放租约，保留可重试/恢复所需事实。

## R3 当前主干动作

主干先抽象为四类能力，不提前锁死尚未确认的业务字段：

- `candidate.acquire`：获取符合已登记范围的候选数据。
- `candidate.filter`：按版本化条件筛选和排序。
- `selection.execute`：执行选品业务动作；具体写入语义需后续补齐。
- `selection.verify`：读取真实结果并生成用户可理解的结果。

具体 Action 名、字段和 HTTP 映射在接口核验完成前不得当作正式契约。

## R4 成功标准

- 用户从统一业务入口完成任务，不接触内部编号。
- 资源、登录态、权限和并发门禁来自当前事实源。
- 选品动作真实执行，结果来自精确回查并能说明对象、状态、时间和来源。
- 任务、租约、运行状态、审计记录保持一致。
- 可重复请求不会产生未预期重复写入。
- 正常、失败、取消、超时和异常退出均能回收运行资源并保留恢复信息。

## R5 失败标准

正确拒绝、门禁失败、外部平台拒绝、数据不符合条件可以作为业务失败返回，但必须有明确原因和可恢复建议。入口不可用、接口未接通、状态未同步、数据未持久化、固定样例冒充真实结果、旧功能退化均属于缺陷或阻断，不得包装成正常失败。

## R6 既有功能回归

必须保护 PortManager 的资源注册、列表、详情、编辑、启停、删除、单项检测、打开、全量检查、登录态同步、租约和运行数据恢复；保护 BSClaw-Local 的模块发现、统一任务状态、资源选择、预检、取消、超时、重试、恢复、结果回查和脱敏审计；保护 HuiceLoginAgent 的独立登录检测边界。
